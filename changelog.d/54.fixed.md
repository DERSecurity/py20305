**A superseded event no longer leaves its modes on the device when it ends
(#54).** A device goes into an event's superseded set when another event takes
over any one of its modes there, and the end-of-event pass left out every such
device, which conflated two things. Nothing was unregistered, so the tracker
went on believing the ended event owned those modes: the event that took them
over released nothing when it ended, and they stayed on the device for good.
And nothing was released, so on a device taken over for only some of its modes
the rest were never disabled either. The event's registration is now removed
for every device it targeted, while the fallback write is still withheld for a
device another event took over entirely -- there the superseding event's own
activation is the write that moves it.
