**A cancelled event's delayed fallback to the DefaultDERControl now runs (#115).** When a running event is cancelled, IEEE 2030.5 §10.2.3.3 has the client wait out the greater of the absolute randomizeStart and randomizeDuration before falling back. The timer that waits it out skipped its callback because the event was already cancelled, so the fallback never ran and the device stayed on the cancelled control until the event left the store. Finished timers were also never forgotten, so a pending-timer check stayed true for the life of the event and held back the default for the whole program. Both are fixed.
