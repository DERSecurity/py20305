**A client can adopt the subscriptions the server already holds for it instead of creating them again (#109).** A client that takes over from another instance of itself, with the same certificate and notification address, used to POST a further subscription for every resource, and a server that does not treat that POST as a renewal (IEEE 2030.5-2023 §8.9.3.4) delivered every notification once per set. With `subscription.adopt_existing: true` the client reads every page of its EndDevice's SubscriptionList when it connects, takes over each subscription whose notificationURI is its own and whose resource it subscribes to, and POSTs only for the rest. `subscription.remove_duplicates: true` also DELETEs further copies of its own subscriptions. A subscription with any other notificationURI is never adopted or removed, nor taken as ours when the client later reconciles with the SubscriptionList, and a server that does not return the list is logged and the client subscribes as before. Embedding code can call `CsipClient.adopt_subscriptions()` or `SubscriptionManager.adopt_existing()`. Both settings are off by default. An adopted subscription is renewed at once under `renewal_method: put`, and on the renewal task's first pass under `post`.

**A client can stop without DELETEing its subscriptions (#109).** `subscription.unsubscribe_on_close: false`, or `CsipClient.shutdown(unsubscribe=False)`, leaves the subscriptions on the server, for an instance that hands over to another instance with the same identity, which adopts them. The default, `true`, keeps the DELETE on shutdown.
