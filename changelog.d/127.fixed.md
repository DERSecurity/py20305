**A change notified within 5 s of the previous change to the same resource is no longer lost (#127).** The client skips a data-change notification for a resource it processed in the last 5 s, so a burst of notifications costs one re-poll. A later notification in that window could report a newer change, and skipping it left the client on the old state until the next scheduled poll, which for tariffs is hourly. A skipped notification now schedules one follow-up re-poll for when the window ends, and further notifications in the window join it. A parent DERProgram notification that a targeted DERControlList fetch has already covered still causes no extra re-poll. TariffProfileList and TimeTariffIntervalList notifications skip the 5 s check, as DERControlList notifications do. Pending follow-ups are cancelled at shutdown.

**A control or price notification that arrives during a rediscovery is re-polled after it (#127).** The re-poll was dropped on the assumption that the rediscovery would read the change, but the rediscovery may already have read that list. While subscriptions suppress polling, the change then waited for the heartbeat poll.

**A price interval that starts or ends between tariff polls is relayed at that moment (#127).** The tariff processor ran only on the tariff poll, so a new interval's price reached connectors up to one pollRate late, often an hour. A timer now runs the processor at the next interval boundary on the server timebase. A failed ConsumptionTariffInterval fetch is retried after 5 s, doubling to 60 s, instead of at the next poll.

**Tariff re-polls run one at a time, and a refresh no longer exposes a partial tariff tree (#127).** Re-polls from the schedule, from notifications and from the boundary timer could interleave, so an older read could be relayed after a newer one. `refresh_tariffs` now builds the tree separately and assigns it when the walk completes; a failed walk keeps the previous tree.

**A DefaultDERControl modified in place is written to the device again (#127).** A modified default keeps its mRID, and the client compared only the mRID, primacy and modes, so the device kept the old settings until an event on the program ended. The client now compares a digest of the default's settings; a new version with the same settings causes no write.

**A DER control missed by a paged or out-of-date read is no longer cancelled (#127).** A server that adds or removes a control between two page reads shifts the later pages, and the read misses a control the server still serves. Cancellation is final, so a control missing from a list read in more than one page is now cancelled only if an immediate second read also misses it. A 404 for a DERControlList no longer counts as an empty list, so a server restart cannot cancel every event of a program; a 204 or an empty list still does. A DERControlList, DefaultDERControl or DERCurveList read that finishes after a read that started later is discarded instead of replacing the newer result.

**Subscriptions are renewed one interval after they were created or renewed (#127).** The renewal loop woke once per interval and skipped a subscription younger than the interval, so a subscription created or adopted after the loop started waited almost two intervals, past the 36 h after which a server may drop it. The loop now wakes when the earliest subscription is due, with passes at least an hour apart at the default 24 h interval.

**Elapsed-time checks use the monotonic clock (#127).** A wall-clock step (an NTP correction, or an operator setting the clock) could start comms-loss handling with no real silence, hide a real one, skip the connection heartbeat probe, stretch the notification dedup window, or move the cancellation wind-down to fallback controls. These now measure elapsed time on the monotonic clock. `seconds_since_last_contact` in the status API does too.
