**A change notified within 5 s of the previous change to the same resource is no longer lost (#127).** The client skips a data-change notification for a resource it processed in the last 5 s, so a burst of notifications costs one re-poll. A later notification in that window could report a newer change, and skipping it left the client on the old state until the next scheduled poll, which for tariffs is hourly. A skipped notification now schedules one follow-up re-poll for when the window ends, and further notifications in the window join it, so the client always reads the latest state. A parent DERProgram notification that a targeted DERControlList fetch has already covered still causes no extra re-poll. TariffProfileList and TimeTariffIntervalList notifications now skip the 5 s check, as DERControlList notifications do, so a price change is relayed at once. Pending follow-ups are cancelled at shutdown.
