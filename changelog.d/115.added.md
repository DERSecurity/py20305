**EndDevices can move from one client process to another without a repeated Response or control (#115).** With `CsipClient(event_state_store=...)` the event processor saves a snapshot of each EndDevice's events, randomized timing, applied default and loss-of-communications boundary to a shared `EventStateStore`, and records each Response as it is posted. `release_devices()` waits for event work already running for the devices, then hands them over without posting or writing anything, and raises if their state cannot be saved; `take_over_devices()` loads their state, rediscovers, carries each event on with its timing, applies a running event only to a device that never received it, and returns False without resuming anything when its rediscovery failed. A Response already posted for a device is not posted again even when no snapshot was saved, and a loss-of-communications boundary or opt-out carried by a device applies to that device only. Event randomization offsets are shared through the store, adjusted for successive events, so an event acting on devices of several processes has one start and end. Without a store nothing changes.
