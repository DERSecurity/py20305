**The initial DefaultDERControl pass no longer writes over a mode a device is
running (#58).** A device with an active event is not a target for its
program's default, which is decided one server-side device at a time. Under a
group lookup the write is not sent that way: each target fans out to every
local device of the program, so a device correctly left out as a target was
written to anyway as part of another target's fan-out, and a default naming a
mode that device was running took it from the event that owned it. The default
now goes out without the modes any running event holds across the program's
devices, as the end-of-event fallback does, and is not sent at all when every
mode it names is being controlled.
